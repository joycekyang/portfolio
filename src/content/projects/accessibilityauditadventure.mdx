## Overview

<MediaSplit
  src="/images/projects/accessibilityauditadventure/screen-1.png"
  alt="Accessibility Audit Adventure title screen"
  caption="Image of the 4 Islands of Accessibility Audit Adventure: Perceivable, Operable, Understandable, and Robust"
  side="right"
  align="center"
  imageWidth="44%"
>
The **Accessibility Audit Adventure** is an immersive micro-learning experience designed to demystify the complexities of digital accessibility for visual designers, instructional designers, and UX/UI students. By utilizing a "cozy-game" aesthetic, the course transforms the often-intimidating Web Content Accessibility Guidelines (WCAG) into an engaging island exploration. Learners navigate through the four pillars of accessibility (**Perceivable, Operable, Understandable, and Robust**, or POUR) in a supportive, low-stress environment that prioritizes practical application over rote memorization.
</MediaSplit>

* **Island One (Perceivable):** Focuses on the principle that information must be able to be seen or heard. The learner proposes that clear, icon-based signage will help the goats (who are red-green colorblind) distinguish between safe and poisonous foods.
* **Island Two (Operable):** Focuses on ensuring interfaces are navigable. The snakes on this island only have stairs, which are inaccessible due to their lack of legs. Learners must propose that universal ramps be added to help with mobility for all.
* **Island Three (Understandable):** Represents the need for content to be easy to follow. Learners are faced with ostriches that cannot find their way to snacks because of obscure and confusing signage. Learners propose that using simple language and predictable signposts will help these islanders.
* **Island Four (Robust):** Focuses on technology being adaptable. Learners encounter rhinos that need an accessible solution for rollercoaster ride boxes to accommodate all sizes. The learners propose an adjustable ride box using different seatbelt lengths as a solution for adaptable design.

## Storyline Features Implemented

<MediaSplit
  src="/images/projects/accessibilityauditadventure/screen-5.png"
  alt="Island Two: Operable universal ramp navigation scenario"
  caption="Island Two: Operable universal ramp navigation scenario"
  side="right"
  imageWidth="44%"
  offsetTop="4px"
  wrap={true}
>
1. **Custom Variables & Progression:** Some Next buttons are locked until the learner interacts with the screen (for example, `Char_Select` requires entering a name and choosing a character). Custom variables track Character Selection, Stars (points) collected, Visited Islands, and Visited Terminology to keep learners motivated and engaged.
2. **Custom Map Navigation:** Custom navigation developed with dynamic object states. Early on, the learner learns how the navigation works and can always return to any island slide using the interactive Map Icon menu.
3. **Modular Slide Layers:** To lower cognitive load and prevent visual clutter, interactions are organized into separate Storyline Slide Layers rather than crowding instructions, feedback, and scenario states onto a single base timeline:
   * **Focused Layers:** Each layer isolates a single part of the experience, such as scenario prompts, interactive puzzles, and targeted feedback, so learners only see what they need at that moment.
   * **Conditional Layer Triggers:** Layer visibility is controlled by variables and object states, allowing learners to revisit clues or retry puzzles without losing progress.
4. **Custom JavaScript:** Because Articulate Storyline’s native timeline does not support smooth, cumulative rotation, I wrote custom JavaScript triggers (using CSS transforms and GSAP inside the Storyline player) to power the stone puzzle:
   * **Incremental Rotation:** Each click runs a JavaScript function that updates the rotation angle of individual stone puzzle pieces, rotating them smoothly until every piece locks into place.
   * **Variable Sync:** Once all pieces reach their target angle, JavaScript automatically updates Storyline variables to unlock the next step and trigger completion feedback.
5. **Audio Sound Effects & Distinct Character Voices:**
   * **Synced Sound Effects:** Layered subtle sound effects, such as the sound of heavy stone shifting into place, synced directly with the JavaScript rotation triggers.
   * **Distinct Character Voices:** Each character has a distinct, conversational voice with natural pacing and tone so learners can easily tell who is speaking.
</MediaSplit>
